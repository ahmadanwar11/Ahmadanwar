# MediTrack Validation Checklist v0.1

Checklist questions follow AOUT (Atomic, Observable, Unambiguous, Traceable). “Yes” is the good answer.

| ID | Item | Answer | Evidence | Where question came from |
|---|---|---|---|---|
| C-01 | Does R-02 specify a measurable response-time limit with a unit? | No | R-02 says “quickly” without a measurable limit. | Document quality / R-02 |
| C-02 | Does R-03 define how the system identifies a conflicting appointment? | No | R-03 states prevention but does not define conflict conditions. | Double-booking risk / R-03 |
| C-03 | Does R-03 specify that two bookings for the same doctor cannot overlap? | No | It says prevent double bookings but does not explicitly define overlap rules. | Double-booking risk / clinic worry |
| C-04 | Does R-04 define whether 15 minutes is a fixed duration for every appointment? | Yes | R-04 says each appointment shall last 15 minutes. | R-04 |
| C-05 | Does R-04 agree with the appointment-length range in R-05? | No | R-04 fixes 15 minutes, while R-05 allows doctors to choose 10–30 minutes. | Contradiction / R-04 and R-05 |
| C-06 | Does R-05 state who can change appointment duration? | Yes | R-05 specifies doctors can set appointment length. | Doctor user / R-05 |
| C-07 | Does R-06 specify how long before an appointment reminders are sent? | No | R-06 only says reminders are sent before appointments. | Forgotten appointments / R-06 |
| C-08 | Does R-06 specify the reminder delivery channel? | No | No channel such as SMS, email, or app notification is named. | Reminder risk / R-06 |
| C-09 | Does R-07 specify a cancellation deadline or restriction? | Yes | It explicitly says patients may cancel at any time. | Patient user / R-07 |
| C-10 | Does R-07 specify how quickly the schedule is updated after cancellation? | No | It requires an update but gives no timing. | Schedule accuracy risk / R-07 |
| C-11 | Does R-07 specify how the receptionist is notified of a cancellation? | No | It says notify the receptionist but does not define method. | Receptionist user / R-07 |
| C-12 | Does R-08 define measurable accessibility or usability criteria for elderly users? | No | “User-friendly for all age groups” is not testable and has no criteria. | Elderly patients / R-08 |
| C-13 | Does R-09 identify which roles may access medical records? | No | Secure storage is stated, but access roles are not described. | Privacy risk / R-09; data protection officer |
| C-14 | Does R-09 specify a security method or protection requirement for stored patient records? | No | “Stored securely” is vague and lacks a specific requirement. | Privacy risk / R-09 |
| C-15 | Does R-10 explicitly cover walk-in appointment booking by receptionists? | Yes | R-10 directly states receptionist booking for walk-in patients. | Receptionist / R-10; walk-in concern |
| C-16 | Does R-11 define how an active appointment is counted? | No | The term “active” is not defined. | Patient booking limit / R-11 |
| C-17 | Does R-12 define the clinic’s normal working hours? | No | Normal working hours are not listed. | Availability / Monday busy period; R-12 |
| C-18 | Does R-13 identify or link to the clinic policy for overdue payments? | No | It refers to clinic policy without naming, attaching, or describing it. | Administrator / R-13 |
